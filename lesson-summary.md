# Основи Express.js та створення RESTful API

**Express** — це найпопулярніший веб-фреймворк для Node.js. Він значно спрощує розробку серверної частини (backend), беручи на себе рутинні задачі, які при використанні стандартного `node:http` доводиться писати вручну (парсинг URL, отримання тіла запиту, встановлення заголовків тощо).

## 1. Маршрутизація (Routing) та обробка запитів [Важливо]

Маршрутизація дозволяє виконувати різний код залежно від URL та HTTP-методу запиту.

**Створення сервера та базові маршрути:**
```javascript
import express from 'express';
const app = express();

app.get('/users/:userId', (req, res) => { ... });
app.post('/users', (req, res) => { ... });

app.listen(3000, () => console.log('Server running!'));
```

### Об'єкт Request (`req`)
Дозволяє отримати вхідні дані від клієнта:
*   `req.params` — параметри з адреси (наприклад, для `/users/:userId` це буде `{ userId: "..." }`).
*   `req.query` — параметри пошуку з URL (наприклад, `?action=delete` дасть `{ action: "delete" }`).
*   `req.body` — тіло запиту (POST, PUT, PATCH). *За замовчуванням недоступне без middleware*.
*   `req.get('Header-Name')` — отримання певного заголовка.

### Об'єкт Response (`res`)
Керує відповіддю сервера:
*   `res.send(data)` — відправляє дані, автоматично визначаючи `Content-Type`.
*   `res.json(obj)` — відправляє JSON.
*   `res.status(code)` — встановлює HTTP-статус (наприклад, `res.status(404).send('Not found')`).
*   `res.sendStatus(code)` — відправляє статус разом із стандартним текстовим повідомленням.

## 2. Проміжні обробники (Middleware) [Важливо]

**Middleware** — це функції, що виконуються в процесі обробки запиту до того, як він дійде до кінцевого обробника. Вони приймають `req`, `res` та функцію `next()`, виклик якої передає керування далі.

**Головні вбудовані та популярні middleware:**
1.  **Читання тіла запиту (JSON):**
    Замість того, щоб збирати дані по шматочках (chunks), використовується готовий middleware:
    ```javascript
    app.use(express.json()); // Тепер req.body міститиме розпарсений JSON
    ```
2.  **Роздача статичних файлів:**
    ```javascript
    app.use(express.static('public')); // Віддає файли з папки public
    ```
3.  **CORS (Cross-Origin Resource Sharing):**
    Захисний механізм браузерів, що блокує запити між різними доменами/портами. Щоб дозволити клієнту (Frontend) спілкуватися з сервером, використовують пакет `cors`:
    ```javascript
    import cors from 'cors';
    app.use(cors()); // Дозволяє всі крос-доменні запити
    ```

## 3. Архітектура MVC (Model-View-Controller) [Важливо]

Щоб код не перетворився на хаос, його розділяють на ізольовані шари (MVC). У контексті API застосунку це:

1.  **Router (Маршрутизатор)** — об'єднує ендпоінти за певним шляхом. Тільки визначає, який метод і адреса викликають певну функцію.
    ```javascript
    // api/todos.router.ts
    const todosRouter = Router();
    todosRouter.get('/', todosController.getAll);
    ```
2.  **Controller (Контролер)** — приймає запит (`req`, `res`), здійснює базову валідацію, передає роботу Сервісу і формує відповідь для клієнта.
    ```javascript
    // api/todos.controller.ts
    export const getAll = async (req, res) => {
      const todos = await todosService.getAll();
      res.json(todos);
    };
    ```
3.  **Service / Model (Сервіс / Модель)** — містить **бізнес-логіку** застосунку. Взаємодіє з базою даних або масивом. Нічого не знає про HTTP, Express, `req` чи `res`.
    ```javascript
    // services/todos.service.ts
    const todos = [];
    export const getAll = () => todos;
    ```

Перевага такого підходу: легке масштабування, тестування окремих частин та заміна компонентів (наприклад, перехід з масиву на реальну базу даних торкнеться лише шару Service).

## 4. Кастомна маршрутизація та Bulk Actions (Групові дії) [Скорочено]

Класичний REST не передбачає роботи з груповими діями (наприклад, "видалити всі виконані задачі"). Найкращий вихід — використовувати метод `PATCH` на колекцію (`/todos`) та передавати тип дії через query-параметри.

**Використання кастомного Middleware для маршрутизації:**
Можна написати власну функцію `isAction`, яка перевірятиме параметр `?action=...` в URL.
*   Якщо умова виконується — викликається `next()` (перехід до обробника).
*   Якщо ні — викликається `next('route')` (пропуск поточного маршруту і перехід до наступного `todosRouter.patch`).

```javascript
todosRouter.patch('/', isAction('delete'), todosController.deleteMany);
todosRouter.patch('/', isAction('update'), todosController.updateMany);
```

## 5. Взаємодія з клієнтом та налаштування проєкту [Скорочено]

*   **Клієнт (Frontend):** Використовує бібліотеку `axios` для надсилання HTTP-запитів (`axios.get`, `axios.post`, `axios.patch` тощо) до нашого Express API. Логіка React-застосунку зводиться до надсилання запиту на сервер і наступного оновлення локального стану (через `reload`).
*   **Інфраструктура:** Сучасні Node.js проєкти налаштовуються з використанням TypeScript (`tsc`, `tsx`), лінтерів (`ESLint`), форматерів (`Prettier`) та хуків (`husky` + `lint-staged`) для підтримання єдиного стилю та якості коду. Для пришвидшення роботи з пакетами рекомендовано використовувати `pnpm`.
